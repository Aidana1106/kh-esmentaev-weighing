# Весовая КХ «Есментаев» — MVP

Учёт взвешивания зерна вместо бумажной тетради. Весовщик выбирает машину и поле и вводит брутто. Тара подставляется сама, нетто считается автоматически, итоги за день по машинам и полям видны сразу. Приложение работает с телефона и без интернета: рейс сохраняется на телефоне и отправляется, когда появится связь.

Версия 1.0.0-mvp · 19.10.2026

## Что входит (Release 1 / MVP)

| История | Где в приложении |

| ZER-6 Проверка веса | Пустые поля, отрицательные числа и тара ≥ брутто не сохраняются. Ошибки подсвечиваются, введённое не теряется |
| ZER-7 Сохранение | Сообщение «Рейс сохранён» или «сохранён на телефоне» |

| ZER-9 Исправление записи | Нажать на рейс в списке (нужна связь) |
| ZER-10 Отметка исправления | Значок «испр.» |
| ZER-11 Итог за день | Вкладка «Итог дня» |
| ZER-12 Итог по машине | Там же; машины без рейсов показываются с нулём |
| ZER-13 Итог по полю | Там же; поля без рейсов помечены «нет рейсов» |

Дополнительно, по НФТ и интервью:
- **Работа без интернета** (интервью №1, WBS 1.3.3). Подробности в [docs/adr/ADR-002](docs/adr/ADR-002-stack-and-offline.md).
- **Две роли** (НФТ-04): `operator` вводит и исправляет рейсы, `admin` дополнительно меняет тару машин и видит журнал исправлений через API.
- **Журнал исправлений** (НФТ-05): пишется с первого дня, и удалить из него ничего нельзя (это запрещает триггер в БД). Экран журнала появится в версии 2 (ZER-16).
- **Русский и казахский** (НФТ-08): кнопка ҚАЗ / РУС, без перезагрузки.
- **Ввод только с клавиатуры** (НФТ-09), **HTTPS** (НФТ-10), **REST + JSON** с понятными кодами ошибок (НФТ-07), **ежедневный бэкап** (НФТ-06), **`docker compose up`** (НФТ-12).
- **Сезон**: накопительный итог за год по полям и машинам.

Не входит (версия 2): фильтр истории по периоду, выгрузка в Excel/CSV, экран журнала исправлений, управление справочниками машин и полей через интерфейс, печать накладной, подключение к табло весов.

## Справочники

Машины: **МТЗ 952, МТЗ 82, МТЗ 80, МТЗ 1025**. Рейс привязан к машине, а не к водителю: водители меняются, машины нет.

Поля: **100 гектар, 200 гектар, Березка, ВзрывПром, Катлаван, Навозка, 409, Давыденовка, Ракета, Балгабай**.

> ⚠️ **Тара машин сейчас тестовая** (6200 / 5800 / 5700 / 6400 кг). Когда заказчик даст реальные значения (ЗВ2), администратор вводит их во вкладке «Машины». Править код не нужно.

## Запуск на сервере (Docker)

Нужны Docker и Docker Compose.

```bash
git clone <репозиторий> && cd kh-weighing
cp .env.example .env          # задать DB_PASSWORD и ADMIN_PASSWORD
docker compose up -d --build  # приложение на http://СЕРВЕР:8000
```

При первом запуске создаются таблицы, справочники и администратор (`ADMIN_LOGIN` / `ADMIN_PASSWORD` из `.env`). Затем заведите учётную запись для весовой:

```bash
docker compose exec app python -m app.cli create-user --login vesovaya --name "Весовая" --role operator
docker compose exec app python -m app.cli list-users
docker compose exec app python -m app.cli set-password --login vesovaya
```

**HTTPS.** Нужен домен, указывающий на сервер, и открытые порты 80 и 443. В `.env` укажите `DOMAIN=ваш.домен` и `COOKIE_SECURE=true`, затем выполните:

```bash
docker compose --profile https up -d --build
```

Caddy сам получит сертификат Let's Encrypt. Без HTTPS офлайн-режим на телефоне не включится: Service Worker работает только на `https://` и `localhost`.

**Бэкап.** Выполните `./scripts/backup.sh` и добавьте его в cron. Пример команды и способ восстановления описаны в начале скрипта.

**На телефоне.** Откройте адрес в Chrome или Safari и выберите «Добавить на главный экран». Приложение откроется как обычное, в том числе без связи.

## Локальная разработка

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
# PostgreSQL 16 должен быть запущен; создайте базы weighing и weighing_test
export DATABASE_URL=postgresql://postgres@127.0.0.1:5432/weighing
export ADMIN_LOGIN=admin ADMIN_PASSWORD=admin123
uvicorn app.main:app --reload                          # http://localhost:8000
```

Документация API (Swagger) открывается по адресу http://localhost:8000/docs.

## Тесты

```bash
pytest -q                     # 25 тестов API на реальном PostgreSQL (база weighing_test очищается)
python scripts/e2e_smoke.py   # браузерная проверка: нужен запущенный сервер и пользователи vesovaya/admin
```

Тесты API проверяют критерии приёмки ZER-1…13, роли, журнал и границу суток по местному времени. Браузерная проверка проходит на экране телефона:
1. Вход.
2. Ошибки ввода.
3. Рейс с автотарой и ручной тарой.
4. Работа без связи: рейс уходит в очередь, переживает перезагрузку и отправляется, когда связь вернулась.
5. Исправление записи.
6. Итоги.
7. Казахский язык.
8. Смена тары администратором.
9. Ввод только с клавиатуры.

CI в GitHub Actions (`.github/workflows/ci.yml`) запускает тесты API на каждый push и PR.

### API

| Метод | Путь | Кто | Что |
|---|---|---|---|
| POST | `/api/auth/login` · `/logout` · GET `/me` | все | вход по логину, сессия 30 дней в cookie |
| GET | `/api/vehicles`, `/api/fields` | вошедшие | справочники |
| PATCH | `/api/vehicles/{id}` `{tare_kg}` | admin | тара на сезон |
| GET | `/api/trips?date=ГГГГ-ММ-ДД` | вошедшие | рейсы за день |
| PUT | `/api/trips/{uuid}` | вошедшие | создать рейс; повтор с тем же uuid не создаёт дубль |
| PATCH | `/api/trips/{uuid}` | вошедшие | исправить; пишет журнал, ставит `is_corrected` |
| GET | `/api/trips/{uuid}/revisions` | admin | журнал исправлений рейса |
| GET | `/api/summary/day?date=` | вошедшие | итог дня: всего, по машинам, по полям |
| GET | `/api/summary/season?year=` | вошедшие | итог сезона |
| GET | `/api/health` | все | проверка доступности (НФТ-02) |

Ошибки возвращаются как `{"code": "tare_ge_gross", "detail": "...", "field": "gross_kg"}` с HTTP 4xx. Фронт переводит `code` на русский или казахский.

### Принятые решения

- **Вес в целых килограммах.** Нетто вычисляет PostgreSQL (`GENERATED ALWAYS AS (gross_kg - tare_kg)`). Проверку `тара < брутто` дублирует ограничение CHECK в базе.
- **Тара копируется в рейс.** Если тару машины поменяют, старые рейсы не пересчитаются.
- **День считается по времени весовой** (`APP_TZ=Asia/Qostanay`, UTC+5). Рейс в 23:50 попадает в свой день, а не в следующий.
- **Время рейса берётся с телефона**, потому что при офлайне рейс может дойти до сервера позже. Время из будущего (больше чем на 10 минут) отклоняется, чтобы поймать сбитые часы.

## Открытые вопросы к заказчику

1. Реальная тара каждого МТЗ (ЗВ2).
2. Меняются ли прицепы между тракторами? Если да, тара зависит от пары «трактор + прицеп».
3. Нужна ли культура в каждом рейсе или достаточно одной на поле за сезон (поле `crop` в справочнике уже есть).
4. Кто вводит вес: весовщик или водитель? Видит ли водитель табло?
