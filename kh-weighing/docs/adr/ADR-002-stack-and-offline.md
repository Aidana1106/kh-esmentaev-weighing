# ADR-002: Стек MVP и работа без интернета

**Статус:** Предложено (на согласование командой)
**Дата:** 19.10.2026
**Автор:** Мырзабекова Тогжан

## Контекст

- MVP по ЛЗ 4: 13 историй (ZER-1…13) и 12 НФТ. Веха 1 — 30.10, «рейс записывается».
- По интервью №1 интернет на весовой нестабильный, а работа без связи входит в MVP. В WBS 1.3.3 это записано так: «запись не теряется при пропадании связи».
- Пользователь работает с телефона. Отдельного устройства на весовой может не быть (ЗВ5).
- Финмодель выбрала вариант 4: собственная разработка на открытом ПО, VPS около 10 $/мес, PostgreSQL.
- НФТ-07 требует REST + JSON, НФТ-12 — запуск через `docker compose up`.

## Решение

1. **Бэкенд: Python 3.12 + FastAPI + PostgreSQL 16 (psycopg 3, чистый SQL без ORM).**
   - Рассматривался ASP.NET Core 8: его команда знает лучше. Отказались, потому что MVP собирался в среде без доступа к NuGet, где проект нельзя было собрать и протестировать.
   - FastAPI даёт проверенный код, автоматическую документацию API (`/docs`) и минимум кода.
   - Схема в SQL-миграциях не зависит от языка, поэтому позже бэкенд можно переписать на .NET без изменений в БД.
2. **Фронт: PWA на чистом JavaScript без сборки**, развитие HTML-прототипа Даны. Нет зависимостей, бэкенд отдаёт фронт сам, на телефоне ставится как приложение.
3. **Работа без интернета:**
   - Рейс сначала записывается в IndexedDB на телефоне (очередь), затем отправляется на сервер.
   - Отправка повторяется при появлении сети, при открытии приложения и раз в 20 секунд. Background Sync не используем: в Safari его нет.
   - `id` рейса — UUID, который генерирует телефон. Сервер принимает `PUT /api/trips/{uuid}` идемпотентно, поэтому повторная отправка не создаёт дубль.
   - Service Worker кэширует оболочку приложения, справочники кэшируются в localStorage.
   - Если сервер отклонил рейс (4xx), рейс помечается «отклонён» и не отправляется повторно. Удалить его можно вручную.
   - Исправлять записи можно только онлайн: так не возникает конфликтов правок.
4. **Авторизация:** сессия в HttpOnly-cookie на 30 дней, токен хранится в БД только в виде хэша. Вход не должен слетать посреди смены без связи.

## Последствия

- Плюс: требования WBS 1.3.3 и НФТ-07, 08, 09, 12 закрыты в первом инкременте.
- Минус: Service Worker работает только по HTTPS (или на localhost). Для пилота на весовой нужен домен с сертификатом (Caddy в docker-compose).
- Минус: время рейса берётся с телефона. Если часы на телефоне сбиты, время будет неверным. Время из будущего отклоняется, время из прошлого — нет (иначе нельзя принять офлайн-рейсы).
- Пересмотреть, если команда решит вести бэкенд на .NET: API и схема остаются прежними.
