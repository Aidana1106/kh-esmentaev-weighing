# Еженедельный статус-отчёт PM: инструкция для команды

## Что это

Каждый понедельник в 09:00 по Костанаю GitHub Actions сам собирает отчёт за прошлую неделю:

1. **Факты** (закрытые задачи, PR, CI, риски) считает код из GitHub API – без модели.
2. **Черновик текста** («итог / сделано / риски / вопросы») пишет локальная модель qwen2.5:7b в Ollama,
   запущенная прямо на раннере GitHub. Данные проекта не уходят во внешние сервисы.
3. PM (Айдана) проверяет черновик по таблице фактов и отправляет команде / заказчику.

Файлы: `scripts/pm_report/status_report.py` (скрипт), `scripts/pm_report/prompt.md` (шаблон промпта),
`.github/workflows/status-report.yml` (расписание), `docs/pm-report/reports/` (отчёты),
`docs/pm-report/verification-log.md` (журнал проверки).

## Как получить отчёт

- **Автоматически:** понедельник утром → Actions → «Статус-отчёт PM» → последний прогон → Summary.
- **Вручную за любые даты:** Actions → «Статус-отчёт PM» → Run workflow → заполнить спринт и даты.
- **Локально:** нужен Ollama (`ollama pull qwen2.5:7b`) и токен только на чтение:
  ```
  pip install -r scripts/requirements.txt
  set GH_TOKEN=...          (PowerShell: $env:GH_TOKEN="...")
  python scripts/pm_report/status_report.py --sprint "Спринт 6" --start 2026-11-24 --end 2026-11-30
  ```
  Без модели, только факты: добавить `--llm none`.

## Как проверять черновик (обязательно, ~5 минут)

1. Откройте отчёт: сверху черновик модели, ниже таблицы фактов.
2. Каждую строку черновика сверьте с таблицами фактов. Номер задачи в тексте → есть ли он в таблице?
3. **Риски переносите из таблицы «Риски», а не из текста модели**: модель пропускает большую часть рисков
   (в проверке ЛЗ 12 – 9 из 12).
4. Удалите общие оценки без фактов («проект почти готов», «команда хорошо поработала»).
5. Технические рекомендации модели (например, «увеличить пул») не отправляйте, пока их не подтвердил разработчик.
6. Неточности записывайте в `docs/pm-report/verification-log.md` – по журналу видно, стоит ли менять промпт или модель.

## Шаблон промпта

Лежит в `scripts/pm_report/prompt.md`. Главные правила в нём: только факты из JSON, номер задачи у каждого
утверждения, числа не пересчитывать, при нехватке данных писать «по данным трекера не видно», не оценивать людей,
4 раздела, до 220 слов. Меняете промпт – прогоните отчёт за прошлый спринт и сравните с журналом проверки.

## Что запрещено передавать в модель

Скрипт передаёт модели только номера, названия и метки задач/PR, даты и посчитанные числа.
Чтобы так оставалось, **запрещено**:

| Нельзя | Почему |
|---|---|
| Токены, пароли, содержимое `.env`, ключи (в т. ч. в названиях и описаниях задач) | Утечка доступа; gitleaks ловит только код, а не тексты задач |
| Персональные данные: ФИО и логины весовщиков, телефоны, адреса | Закон РК о персональных данных; модель и логи – не место для них |
| Реальные веса и итоги урожая заказчика, выгрузки из базы | Коммерческие данные КХ «Есментаев» |
| Тексты переписки с заказчиком, протоколы с подписями | Конфиденциально, нужен отдельный разговор с заказчиком |
| Логины GitHub участников и оценки работы людей | Отчёт о задачах, а не о людях |
| Любые данные во **внешние** API (ChatGPT и т. п.) без согласования | Локальная модель выбрана именно для того, чтобы данные не покидали раннер |

Поэтому в названиях задач не пишем фамилии и реальные данные заказчика – это правило теперь и для трекера.
