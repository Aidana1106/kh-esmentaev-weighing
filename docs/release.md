# Релизный план

## Окна релизов

| Когда | Почему |
|---|---|
| Вторник и четверг, 19:00–20:00 по Костанаю | Весовщик работает днём, вечером нагрузки нет; до выходных остаётся время, чтобы исправить |
| Не выпускаем | В пятницу, в выходные и накануне праздников; днём во время взвешивания; 10.12 – накануне приёмки |
| Срочное исправление | Вне окна, только класс «Срочный» (ошибка в нетто, не открывается форма), с тем же чек-листом |

## Коммуникация с заказчиком

- За день до релиза: что меняется, когда, займёт ли время (сообщение в WhatsApp).
- Сразу после: «обновили, всё работает» или «откатили на прошлую версию, данные целы».
- Если откат: в течение суток – что случилось и когда будет исправление.

## Чек-лист релиза

1. PR влит в main, CI на main зелёный (ссылка на прогон в задаче).
2. Сейчас окно релиза, заказчик предупреждён накануне.
3. Свежая резервная копия: `./scripts/backup.sh`, файл не пустой.
4. Записать текущую версию: `git rev-parse HEAD` – это точка отката.
5. Выложить: `git pull && docker compose up -d --build`.
6. `docker compose ps` – все сервисы healthy, `/api/health` отвечает 200.
7. Проверка с телефона: вход, сохранить рейс, увидеть его в итогах дня (или `scripts/e2e_smoke.py`).
8. Сообщить заказчику, записать релиз в задачу.

## Чек-лист отката

1. **Решение об откате принимает ответственный за релиз (Тоғжан) единолично, без согласования, не позже 10 минут после выкладки**, если упал healthcheck, не прошла проверка с телефона или весовщик не может сохранить рейс. Если его нет – Айдана.
2. Написать команде «откат» в общий чат.
3. Вернуть прошлую версию: `git checkout <версия из п. 4 релиза> && docker compose up -d --build`.
4. Если релиз менял базу (новая миграция) – восстановить копию из п. 3 релиза:
   `gunzip -c backups/weighing-ДАТА.sql.gz | docker compose exec -T db psql -U weighing -d weighing`.
   Рейсы, введённые после выкладки, сверить с тетрадью весовщика.
5. Проверить `/api/health` и сценарий с телефона.
6. Айдана сообщает заказчику.
7. Записать инцидент в `docs/incidents.md`, завести задачу-дефект в класс «Срочный».

Цель: откат занимает не больше 15 минут от решения до рабочей версии.
